# Requirements Quality Checklist

- [x] Problem and research objective are explicit.
- [x] The 60% objective is aspirational, measurable, and not a guarantee.
- [x] CAGR and arithmetic average yearly return are distinct metrics.
- [x] Point-in-time membership and security identity are dependencies.
- [x] Canonical 8-year train / 2-year forward boundaries are explicit.
- [x] Forward periods cannot influence candidate selection.
- [x] Trade-frequency, execution, costs, and tax assumptions are testable.
- [x] Prior prototypes and invalid results are documented as benchmarks.
- [x] Baselines are explicitly controls, not finalized strategies.
- [x] The complete indicator program is decomposed into independently tested tasks.
- [x] Historical acquisition-union symbols cannot enter outside daily membership.
- [x] Repeated searches are immutable, bounded, and retain every candidate outcome.
- [x] DuckDB persistence and reproducibility lineage are specified.
- [x] Daily scanning is separated from order execution.
- [x] Index/provider neutrality has a second-index acceptance scenario.
- [x] No API key or private data path appears in the specification.
- [x] Deployment maximum drawdown is capped at 40%; an experiment may be stricter.
